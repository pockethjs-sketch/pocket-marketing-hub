# Google Sheets 연동 현황

## 현재 결론

현재 상태는 **원장 준비 완료 / 웹 연동 0%**입니다.

- 비공개 Google Sheets 원장에는 고객사·프로젝트·업무·KPI 정의를 위한 초기 스키마와 시드 데이터가 있습니다.
- 공개 웹은 `frontend/src/data/demoData.js`의 비식별 샘플만 읽습니다.
- 공개 웹에는 Google Sheet ID, Apps Script URL, 비밀 토큰 또는 운영 API 주소가 없습니다.
- 시트 수정 내용은 웹에 자동 반영되지 않습니다.
- 웹의 `업무 추가`, `콘텐츠 추가`, `자료 등록` 등 입력 화면은 현재 데모 UI이며 Google Sheets에 저장되지 않습니다.
- 검색, 필터, 고객사 선택, 역할 전환도 브라우저 메모리에서만 동작합니다. 새로고침 후 보존되는 운영 데이터가 아닙니다.

따라서 현재 웹 화면의 업무 건수, 완료율, 콘텐츠, KPI 값, 최근 활동은 운영 원장 집계가 아니라 화면 검증용 데이터입니다.

## 현재 데이터 경계

| 구분 | 현재 데이터 원천 | 영속 저장 | 운영 사용 가능 여부 |
|---|---|---:|---|
| 공개 웹 화면 | 비식별 데모 JS | 아니요 | UI 검증만 가능 |
| Google Sheets 원장 | 초기 스키마·시드 | 예 | 백엔드 연결 전에는 웹과 분리 |
| 업무·콘텐츠·자료 추가 버튼 | 미구현 | 아니요 | 입력값 저장 불가 |
| 역할 전환 | 브라우저 데모 상태 | 아니요 | 실제 권한으로 사용 불가 |
| 채널 성과 동기화 | 미설정 | 아니요 | API 연동 후 사용 가능 |
| 활동로그 | 초기 이관 이벤트 | 예 | 실제 웹 변경 이벤트는 아직 없음 |

## 원장에 준비된 범위

원장은 다음 관계를 불변 ID로 연결하도록 설계돼 있습니다.

`고객사 → 프로젝트 → 업무·콘텐츠 → 승인·성과 → 파일·활동로그`

초기 원장에는 UND 고객사·프로젝트, 103개 업무, 22개 KPI 정의와 업무 템플릿이 들어 있습니다. 콘텐츠, 콘텐츠 버전, 승인, 성과 일별, KPI 실적은 운영 입력을 받기 위한 빈 원장입니다. 외부 채널 API는 아직 연결되지 않았습니다.

세부 탭과 필드 정의는 [데이터 모델](DATA_MODEL.md), 화면별 읽기 구조는 [API 계약](API_CONTRACT.md)을 기준으로 합니다.

## P0: 공개 범위 코드 불일치

운영 연결 전에 반드시 한 가지 공개 범위 체계로 통일해야 합니다.

- API 계약: `POCKET_ONLY`, `PROJECT_TEAM`, `CLIENT`
- 현재 원장 코드: `INTERNAL`, `CLIENT`

이 상태에서 바로 연결하면 포켓 내부 정보와 실행사 정보의 경계가 모호해집니다. 또한 초기 이관된 업무가 광범위하게 고객 공개로 설정되어 있으므로 실제 고객에게 공개할 업무를 다시 선별해야 합니다.

권장 기준은 다음 세 단계입니다.

| 코드 | 공개 대상 | 포함 예시 |
|---|---|---|
| `POCKET_ONLY` | 포켓 내부 | 전략, 원가, 위험, 계약 기준, 내부 메모 |
| `PROJECT_TEAM` | 포켓 + 배정 실행사 | 제작 지시, 작업 메모, 실행사 담당 정보 |
| `CLIENT` | 고객사 | 일정, 공개 결과물, 승인 요청, 공개 성과 |

코드 통일과 기존 행 마이그레이션이 끝나기 전에는 운영 데이터를 공개 웹에 연결하지 않습니다.

## 안전한 목표 구조

```text
GitHub Pages 프런트엔드
        ↓ HTTPS
인증 프록시 또는 Apps Script API
        ├─ 로그인 세션 확인
        ├─ 사용자·프로젝트 권한 확인
        ├─ 역할별 응답 필드 화이트리스트
        ├─ 입력 검증·동시 저장 제어
        └─ 활동로그 기록
        ↓
비공개 Google Sheets 원장
```

브라우저가 보낸 `role`, `client_id`, `project_id`는 권한 근거로 신뢰하지 않습니다. 서버가 로그인 사용자와 프로젝트 권한표를 기준으로 접근 범위를 다시 계산해야 합니다. 시트 원본은 비공개로 유지하고 고객에게 직접 공유하지 않습니다.

## 읽기 연동 구현 순서

1. 실제 사용자와 프로젝트 권한을 원장에 등록합니다.
2. 공개 범위 코드를 통일하고 고객 공개 행을 검수합니다.
3. `bootstrap`으로 로그인 사용자가 볼 수 있는 고객사·프로젝트만 반환합니다.
4. `project_overview`, `tasks`, `contents`, `approvals`, `performance`, `files`, `activity`를 화면 단위로 지연 조회합니다.
5. 모든 응답에서 `archived_at` 행을 제외하고 역할별 공개 필드만 반환합니다.
6. 프런트의 하드코딩 집계와 `demoData.js`를 API 응답으로 교체합니다.
7. 로딩, 빈 상태, 오류, 재시도, 마지막 동기화 시각을 화면에 표시합니다.

## 쓰기 연동 구현 순서

1. 추가·수정 폼이 `mutation_id`와 `expected_row_version`을 포함해 `POST action=mutate`를 호출합니다.
2. 서버가 로그인 세션, 프로젝트 권한, 허용 필드, 데이터 타입, 코드값, 참조 무결성을 검증합니다.
3. `LockService`로 같은 원장의 동시 저장을 잠급니다.
4. 불변 ID로 대상 행을 생성하거나 필요한 필드만 수정합니다.
5. 동일 작업을 `15_활동로그`에 PREPARE → COMMIT 순서로 추가합니다.
6. 동일 `mutation_id` 재요청은 중복 저장하지 않고 기존 성공 결과를 반환합니다.
7. 삭제는 행 삭제 대신 `archived_at` 보관으로 처리합니다.
8. 저장 성공 응답을 받은 뒤에만 화면을 확정 상태로 변경합니다.

구체적인 저장 규칙은 [저장·연동 원칙](STORAGE_AND_SYNC.md), 인증과 비밀값 기준은 [보안 경계](SECURITY_BOUNDARY.md)를 따릅니다.

## 구현 우선순위

### P0 — 운영 연결 전 필수

- 공개 범위 코드 통일 및 기존 업무 공개 범위 재분류
- 실제 사용자·조직·프로젝트 권한 등록
- 서버측 인증과 고객사/프로젝트 격리
- 비밀값을 Script Properties 또는 백엔드 환경 변수로 이동
- 고객 A가 고객 B의 데이터를 요청할 때 403을 반환하는 테스트

### P1 — 실제 조회·저장

- 화면별 읽기 API와 프런트 데이터 어댑터
- 업무·콘텐츠·파일 생성·수정·보관 API
- `mutation_id`, `row_version`, `LockService`, 활동로그 구현
- 로딩·오류·재시도·저장 상태 UI

### P2 — 성과와 외부 채널

- 유튜브·메타·네이버·구글 데이터 수집
- 원천 성과와 KPI 집계 분리
- 동기화 상태, 마지막 성공 시각, 실패 사유 표시

### P3 — 운영 안정성

- 매일 별도 Drive 폴더에 백업하고 최소 30일 보관
- 실제 복원 훈련
- 저장·동기화 오류 알림
- 권한 격리, 중복 요청, 동시 수정, 보관·복원 자동 테스트

## 운영 연결 완료 판정

다음 조건을 모두 만족하기 전에는 화면에 `Google Sheets 연동 완료`를 표시하지 않습니다.

- 실제 사용자 인증과 프로젝트 권한 검증 성공
- 공개 범위 코드 통일과 고객 공개 데이터 검수 완료
- 화면의 수치가 원장 행으로 역추적 가능
- 웹 입력이 원장 행과 활동로그에 함께 기록됨
- 중복 요청과 동시 수정 테스트 통과
- 고객사 간 데이터 격리 테스트 통과
- 백업 생성과 복원 테스트 통과
