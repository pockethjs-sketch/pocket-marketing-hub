# 성과 추적 화면 기준

## 목적

`성과` 화면은 KPI 정의·목표 관리용이고, `성과 추적` 화면은 실행이 실제 고객 반응으로 이어지는 구간을 찾는 진단용입니다. 두 화면의 책임을 섞지 않습니다.

## 데이터 흐름

```text
12_성과일별 노출
  → 반응
  → 클릭
  → 문의
  → 전환·매출
```

- 채널·일별 실적: `12_성과일별`
- 고객 공개 채널: `05_프로젝트채널.customer_visible`

## 계산 규칙

- 단계 전환율 = 현재 단계 합계 ÷ 직전 단계 합계 × 100
- 최대 이탈 구간 = 전환율이 가장 낮은 유효 구간
- CTR = 클릭 ÷ 노출 × 100
- 문의당 비용 = 광고비 ÷ 문의 수

분모가 0이면 0%로 가장하지 않고 `데이터 없음`으로 처리합니다. 서로 다른 채널의 값은 `12_성과일별`에서 같은 프로젝트·기간으로만 합산합니다.

## 제품 분석 도구에서 차용한 원칙

- 신규 사용자 획득과 세션 유입을 분리하는 GA4 방식처럼 데이터의 기준 시점을 혼합하지 않습니다.
- Amplitude 퍼널처럼 순서가 있는 단계의 전환과 최대 이탈을 함께 봅니다.
- Airbridge처럼 개요·추이·퍼널·채널 분해를 같은 기간 필터로 묶습니다.
- HubSpot처럼 접점과 최종 성과를 구분하며, 현재 버전은 멀티터치 매출 기여를 임의 추정하지 않습니다.

현재 외부 채널 API 자동 수집은 연결되지 않았습니다. 따라서 원장에 없는 매체 실적이나 매출은 화면에서 생성하지 않습니다.

`performance_tracking`은 탭 진입 시 `12_성과일별`만 읽는 경량 API입니다. 업무·콘텐츠·승인·KPI 원장을 한 요청에서 중복 조회하면 Apps Script 응답이 30초 이상 지연되므로, 해당 데이터는 기존 업무·콘텐츠·성과 화면의 책임으로 유지합니다.
